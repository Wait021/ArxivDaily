### [OS-Omni: Benchmarking Generalist Computer-Using Agents on Long-Horizon Workflows Across Platforms](https://arxiv.org/abs/2611.34232)

`2611.34232` · 2026-11-25 · [PDF](https://arxiv.org/pdf/2611.34232)

#### 概览
论文类型：基准/系统论文（附带九个模型的实证评测）。OS-Omni 用“六平台统一执行环境 + 18 个自研可控应用 + 最终态可执行评测器”来测通用计算机使用智能体能否完成跨平台、长视程、带持久状态的工作流；最过硬的证据是全部 300 个任务均通过 oracle 执行验证与失败态测试（表 5），加上表 1 的九模型与人类参考对比。我判断：基准工程可信度较高，实证结论方向可信但精度受限——单次运行、每平台仅 48 题、无方差与无效运行率报告，且“平台鲁棒性”的归因存在混杂。

#### 问题与思路
要解决的问题：一个通用智能体能否可靠完成横跨 Windows/Ubuntu/macOS/iOS/Android/Web 的长视程、有状态工作流（引言例子：比价加购物车、更新桌面预算表、在手机建日历、导出文档并发消息，只能靠检查购物车、记录、日历、文件与消息的最终状态判分）。值得解决的理由：作者称现有基准各测一个软件面，单一基准上的高分难以解读为通用计算机使用能力。

之前的做法差在哪（论文对比的几类）：浏览器基准（WebArena、VisualWebArena、WorkArena、Mind2Web 等）只覆盖网页；AndroidWorld 只覆盖安卓；OSWorld、WindowsAgentArena、macOSWorld、WorldGUI 等把评测推进到真实桌面执行环境，但 OSWorld 仅桌面单平台，且依赖真实应用，无法复位涉及账号、购物车、支付的持久服务态；各基准的平台范围、动作接口与计分协议互不兼容。

核心直觉：把跨平台覆盖、长视程（任务按人类操作步数校准难度）与最终态判分三轴耦合，用自研“Open 系列”应用（支撑 v1 的 180/300 任务，60.0%）提供可复位、可查询的持久状态。走一个具体例子：输入是 OpenBank 指令“创建三个收款人、提交三笔转账、安排两笔账单支付、提交两笔争议，完成后保持前台”，应用状态由种子数据初始化、固定业务日期 2026-06-01（C.3 节）；过程中智能体每步收到截图与最近 3 步历史，先写短反思再输出一个动作块（桌面为受限 PyAutoGUI 沙箱，Android 为 adb 命令块，图 11），单平台任务上限 300 步、每步 180 秒；输出上，终止后评测器直接查本地数据库与业务事件记录——图 37 里 GPT-6-Astra 跑 99 步自报完成，评测器发现 84.25 的 Elliot Stone 转账被提交了两次（"The transfer had to exist exactly once"），判 FAIL。“界面看似完成、持久态不正确”正是该基准要抓的失败。

#### 最脆弱的一环
“当前智能体远未达到平台鲁棒”这条头条结论依赖跨车道数字可比，但各车道的智能体侧接口不同（桌面发 PyAutoGUI 代码、Android 发 adb 命令块、iOS 用另一套后端），且表 1 未报告各车道无效运行率。若 iOS/macOS 车道含更多接口或基础设施摩擦，33.5/25.6 分的缺口会部分是评测面而非模型面的产物；反过来，Linux 车道与 OSWorld（Ubuntu + PyAutoGUI，B.3.1 自述“matches the OSWorld baselines”）分布最接近，模型训练数据见过类似轨迹的概率更高——我推断 Linux 上的领先部分反映分布邻近。跨车道可比性一旦动摇，平台不均衡的结论跟着动摇。最小检验：在 iOS 与 Linux 两车道用共享的结构化动作模式（B.3.2 称其已跨桌面/移动/网页共用）重跑三个前沿模型，并按车道报告无效运行率，看缺口是否变化。

- 摘要将 67.54 步表述为"OS-Omni tasks"所需，实为五平台均值且不含 Web 与跨设备（附录 A）；200.97 秒对比的是 OSWorld 中位数 111.94 秒。影响：小；把握：高（原文可查）。

### [ACAP: Asynchronous Coding Agents for Efficient Robot Control](https://arxiv.org/abs/2611.31205)

`2611.31205` · 2026-11-23 · [PDF](https://arxiv.org/pdf/2611.31205)

#### 概览
论文类型：系统/方法论文（框架设计 + 真机实证评测），附带数据集发布。ACAP 把一台机器人组织成一队持久编码智能体，每个成员负责一个“控制组”（如左臂+夹爪、躯干+底盘），独立跑观察-推理-编码-执行循环；一个 hyper-agent 负责分派任务、授权共享工作区访问，并在紧耦合操作时把控制权收回给 lead 直接控制，以此解决单智能体串行推理阻塞独立动作的问题。最过硬的证据是两项真机研究的结果一致：25 个任务/平台设置的任务覆盖研究降时间成本 28.2%（摘要；表1 全设置 19.04→13.67 分钟），90 次 rollout 的重复试验降 29.4%（5.3 节；表3 六任务均值 21.43→15.14 分钟）。我判断：在其报告的设置内结果可信、报告较诚实，但缺显著性检验、评分者一致性信息与外部基线，机制归因有混杂可能，外推需谨慎。

#### 问题与思路
- 要解决的问题：编码智能体策略把“写程序控机器人”变成持续交互（Code as Policies 的延伸），但典型实现由单个 agent 管整台机器人。作者称它虽能下发并行运动指令（4.2 节明确 Direct 有此能力），所有组件的决策仍走同一个推理循环，一侧诊断抓取失败会延迟另一侧的独立动作；真机上推理耗时是主要开销，值得解决。
- 论文自己对比的两类做法：Direct——单 agent 全局控制，推理串行；Fixed Delegation——lead 分派任务、成员各控其组、控制权永不回收，紧耦合操作时反复通信同步，开销大，且一个成员的恢复动作会改变物体状态、作废另一成员的计划。相关工作中的 LLMCompiler、DAG-Plan、EMOS、BiCICLe 等被引用但未进入实验。
- 核心直觉：独立推理可以并行，物理依赖交给一个协调者按执行反馈动态处理——给共享资源排序访问，或收回控制权由 lead 直接做联合动作。脚手架四件套（3.3 节）：持久上下文（跨交接保留会话与生成程序）、消息缓冲（确认前不丢）、事件等待（只阻塞必要动作）、独占控制权（每组同时只有一个所有者可下指令，交接不中断运动、不松开已抓物体）。4.4 节说明 hyper-agent 与 lead 实为同一会话。
- 例子（图1）：输入是“插四支花入瓶”的指令与场景观测。两成员并行抓取、取向花枝，进瓶需 hyper-agent 授权且一次一支，等待成员在他人插入时继续准备下一支，9.1 min 四花完成。毛巾折叠相反：成员并行建立双臂抓取，lead 接管双臂做联合折叠，再委托成员收尾，15.1 min 完成。输出为机器人动作序列与任务完成状态。

#### 概览
论文类型：方法论文（长文档翻译智能体 + 离线偏好优化训练），实证评测为辅。LOONG 用三层记忆（段摘要、句对、实体记录）加三步“观察-行动”的上下文筛选，再用采样轨迹构造的偏好数据做 SFT+DPO，解决长文档翻译中上下文窗口受限、检索到的历史上下文含冗余噪声伤质量的问题。最过硬的证据是 Table 2：四个 backbone × 两个数据集 × 双方向的聚合平均分全部超过最强基线 DELTA，且 Table 3 有组件与训练消融；但聚合优势多在 1 分上下，全部结论建立在与训练信号同源的自动指标和一个未经人工校验的 GPT-4.1 评测上。我的总体判断：方向可信、消融完整，但摘要量级数字（13.0 分）与“一致最优”的表述有夸大，可靠性中等。

#### 问题与思路
- 要解决的问题：LLm 做文档级翻译（DocMT）时上下文窗口有限，术语与文体跨段漂移；带记忆的 agent 把检索结果不加区分塞进 prompt，冗余上下文反而降低质量（引言引 Karpinska & Iyyer 2023）；全历史进对话的 Doc2Doc 做法在超长文档上直接超出窗口（图 1 中 156–160 行失败）。
- 论文对比的四类做法：Sentence（逐句孤立翻）、Segment（分段无跨段上下文）、Doc2Doc（Wang et al. 2023a，全历史对话式）、DELTA（同组 ICLR 2025 前作，多粒度记忆、不做过滤）。LOONG 的 3E 记忆明确沿用 DELTA 设计（原文"Similar to Wang et al. (2025c)"），增量在筛选机制与训练。
- 核心直觉：模仿译员“边翻边记、动笔前先查笔记”。源文档切段（§4.1 写每段 5 句，Limitations 写 10 句，两处矛盾），每翻完一段更新三层记忆：Essence（各段不超过 50 词摘要）、Exemplar（已完成源-译句对）、Entity（实体双语名与角色等属性，六类 schema）。翻下一段前执行三步推理，每步先逐条分析候选与当前段的相关性再输出选中子集，依次处理摘要、句对、实体。选择策略靠采样学出：每步采 M=7 个动作、每动作采 N=5 个翻译，用 sCOMET 均分作效用，取最优/最差动作构成选择偏好对，取最优/最差翻译构成翻译偏好对，先 SFT 冷启动再 DPO（LoRA）。推理时每步只采样一次，输出经“句首 #i、句界 <s>/<s> 标记 + 失配递归二分”的算法强制句级对齐。
- 具体例子（附录 A.3，Table 13，军事科幻网文）：当前段写科伦和尼米奇走向车场。Essence 检索 4 条摘要，推理只选中第 4 条（士兵被叫醒整备出发，衔接当前场景）；句对候选选中第 3、4 条，第 4 条恰好钉死“博拉丁·肖上尉=Captain Borlatin Xiao”及科伦的中尉军衔；10 条实体记录筛到 2 条，并识别第 10 条与第 5 条重复而丢弃。输出人名全程一致；同段句子级基线把同一人翻成 Cole、Kolen、Korm，还虚构出原文没有的"Admiral Nimitz"。

主结论依赖的对比没有分离“工具访问”与“RL 训练”两个因素。Table 3 中 NeoAMT-8B（22.34 exact）对 GRPO-8B（17.63）的差异同时包含检索工具可用、R_neo 奖励、RQE 与带搜索的 prompt。论文中最接近“同工具、未训练”的对照是 Figure 5（正文称 Qwen3-8B 与 NeoAMT-8B 配置同一检索工具与 prompt，zh-en XCOMET-XL 68.3 对 79.7），但未进主表、未报告新词指标，且 XCOMET-XL 本身是训练奖励的组成部分；Table 31 显示仅借好查询做 RAG（无 RL）exact 即达 23.68，超过 NeoAMT-8B 的 22.34。若补上“Qwen3-8B/32B + 同一工具 + 同一 agentic prompt、不训练”的对照后新词指标接近 NeoAMT，“RL 框架”的实际贡献就收缩为保持整体质量与生成好查询。最小检验：将该对照加入 Table 3 全指标，并补一个“有搜索、无 R_neo”的奖励消融。

1. 评测语言失衡：主表 743 例中 zh-en 占 578（换算约 78%），en→xx 方向仅评 en-ja/en-zh 共 270 例（§2.1、Table 27/5）。影响：结论主要反映 zh-en。把握：高。

3. 训练数据与 judge 同源：训练翻译由 gpt-5-2025-08-07 合成，评测 judge 亦为 gpt-5-2025-08-07，人工验证仅覆盖 2 个语言对（Table 25）。把握：高；影响：多语言泛化声明受限，judge 存在风格偏置风险。
4. 自适应采样公式疑似符号错误（见证据核查第 4 行）。把握：中；影响：RQE 结论的可复现性。
5. 全文未报告多次运行方差或显著性。影响：几分点的差距（如 Table 7 的 22.34 对 20.19）稳定性未知。把握：高。
6. 测试集新词与检索语料来自同一 Wiktionary dump，§5.4 报告 76.71% 的相关查询能检回新词定义——任务实质是“答案可查的字典翻译”。这与论文定位一致，但外推到词典尚未收录的真实新词时，方法前提是词典能及时更新。把握：高。

直接服务于方向①（翻译智能体与 MT 评测）：
- 论文报告的可复用配方：GRPO + 检索 token loss masking（沿 Search-R1/ARPO）、format 门控奖励、术语命中率与 QE 组合奖励（λ=0.1）、检索缓存、最多 3 轮搜索、8×A100 约 40 小时（附录 A.2），可直接作为我富结构文档翻译 agent 的训练骨架。

### [Confirming Correct, Missing the Rest: LLM Tutoring Agents Struggle Where Feedback Matters Most](http://arxiv.org/abs/2605.16207v1)

`2605.16207v1` · 2026-05-15 · [PDF](https://arxiv.org/pdf/2605.16207v1)

#### 概览
论文类型：基准类为主（提出新基准并做大规模自动评测），辅以小规模人工评估的实证论文。作者把一个真实命题逻辑辅导系统里 32 道题的全部有效推导路径编码为知识图谱（KG）作为穷举真值，检验 7 个 LLM 反馈智能体能否把学生的单步解区分为“最优 / 有效替代 / 错误”三类，并评其反馈的教学质量。最过硬的证据是 10,836 对解–反馈上的分类结果（表 2，温度 0.0，CI ±5–8%）：最优步 F1 0.94–0.99，有效替代步 F1 0–0.76，错误步 F1 0.04–0.55。总体判断：核心失败模式（次优步误拒、错误步误纳）在该设置下可信；跨模型排序与“模型级归因”受自配对设计混淆，需打折；稿件含未填占位符，处于草稿状态。

#### 问题与思路
- 要解决的问题：辅导科学中的 assistance dilemma——把有效但绕路的推理判成错误会压制探索，全盘接受又会固化低效策略。ITS 靠人工解法图做步级三分类诊断，但每题需专家建模、难扩展。LLM 能补灵活性与可扩展性，但其诊断精度从未被测过。
- 论文对比的先前做法及其不足（§2）：先前 LLM 辅导评测依赖二值正确性标签，掩盖了“有效替代”类；现有逻辑基准不适配——ProofWriter 只评最终证明有效性，FOLIO 惩罚有效替代推导，ProntoQA 无法表示多规则分叉点，LogicLearner 数据不可得；角色分工式反馈流水线能否做细粒度三分类诊断不明。
- 核心直觉：命题逻辑前提有限、规则集封闭（15 条），前向链可穷举全部有效推导，KG 因此给出无争议的三分类真值；每条边还标注所用规则与父语句，可同时验证“推出了什么”与“推导是否正当”——符号上正确但规则或父语句误用仍判 Incorrect。
- 具体例子（图 2、例 2）：输入证明状态 1.(B↔¬J), 2.(¬N∨J), 3.(B∨¬N), 4.((B→¬J)∧(¬J→B)), 5.(N→J), 6.(¬B→¬N)；学生模型（某 LLM 模拟）提出“推导 (B→¬N)，因为它与结论同形、可由 (¬B→¬N) 的逆否式得到”；KG 查无可推出该步的边，真值为 Incorrect；Teacher 代理拿到解法上下文“用 Commutative 从 (¬N∨J) 推 (J∨¬N)”，却回复表扬其逆否推理——错误步被当作有效，记一次 over-validation。整体流程：516 个真实证明状态（32 题、5 个难度级、单一课程日志）× 7 模型（每模型先生成带推理轨迹的下一步，再在 Peer/Teacher/Judge 三条件下当反馈者）× 3 条件 = 10,836 对，配自动指标（F1、OR、OV）加每条件 100 对的人工四维评分（1–3 分）。

4. 摘要的 "architectural rather than informational limits" 超出实验覆盖（仅测提示级信息注入），§7 自己的表述 "prompt-level layering alone cannot ensure adaptive feedback" 更准确。影响：摘要读者会高估结论范围。把握：高。

#### 对我的价值
论文本身的发现（对③教学智能体线直接相关）：三分类诊断加 KG 穷举真值加 OR/OV 两个条件错误率，是“多正确答案”场景下超越二值正确性的评测设计，可直接用于我构建辅导与反馈智能体的评测；三条失败结论是系统设计的反面数据点——提示级信息注入不改诊断（η²<.01）、同模型 Judge 锚定 Peer 错误、诊断正确也未必给出可行动反馈，提示需要独立诊断信号（外部验证器或接地分类器），单靠堆叠提示层角色解决不了诊断。

对通用兴趣（多智能体协作、工具调用）：论文在该域提供了一个数据点——角色分工与自验证在单一设置下无增益甚至传播错误，支持“验证需独立接地信号”的设计取向。

我的推断（对①翻译线，一条可迁移思路）：XML/PPT 等富结构文档翻译的反馈评测有同构问题——结构合法性可由机器穷举验证（类比 KG），译文存在多个可接受版本（类比 valid-alternative），可把“把有效改写判为错误”和“把漏译或结构破坏判为有效”定义成翻译反馈智能体的 OR/OV 指标。此为类比，原文只覆盖逻辑证明域。

②生物智能体线关系不大：该方法依赖封闭规则空间可穷举，药物发现不具备此条件，不硬找联系。

#### 结论
值得浏览。表 2 的 OR/OV 失败模式与“KG 真值三分类”的评测设计对我做教学智能体评测有直接参考，但单域草稿、自配对混淆、部分数字无法核对；精读 §3.3、§5–6 与表 2 即可吸收其价值。

### [Who You Explain To Matters: Learning by Explaining to Conversational Agents with Different Pedagogical Roles](http://arxiv.org/abs/2601.16583v1)

#### 最脆弱的一环
摘要里“Challenger 促进认知与元认知行为”这类主张依赖的对话编码比较（表 3）没有统计检验，也没有按产出量归一化。若各组的元认知次数差异主要来自消息总量——Challenger 字数 351.88、Peer 179.25，49 次 vs 36 次发生在约两倍文本量上（换算），按密度算 Challenger 未必占优——“角色塑造认知/元认知行为模式”这半条结论就退化为“角色改变了产出总量”，RQ1 的回答随之打折。检验的最小做法：用已收集的对话，把各类编码次数按消息数或字数归一化后做卡方或泊松回归（无需新实验），同时补一个角色感知的操纵检验问卷。

#### 边界
作者承认的局限（§6.4）：
- 单次约 60 分钟会话，无法回答多会话下角色效应是否累积或衰减；
- 只在经济学概念学习一个领域内做，角色—领域适配（Tutee 宜概念建构、Challenger 宜论证任务）未验证；

我的质疑：
1. 角色与实现捆绑（§4.1、附录 A）：三条件除人设外，行为结构本身不同——Tutee 带 Bloom 层次筛查与知识状态更新，Peer 带评估—行动框架，Challenger 带五类提问选择。引言称要“隔离角色效应”，实际隔离的是“角色+配套行为”整包。影响：结论应读作“这三种具体设计之间存在差异”，向其他实现同一角色的系统推广需谨慎。把握：较大。
2. 零结果的用法（§5.2.1、§6.2）：每组 n=24 且未报告功效分析，讨论却把“客观成绩无差异”直接转为“设计决策应转向体验指标”的依据。若 Tutee（后测 16.83，其他组 15.04–15.46）存在被检出力掩盖的小差异，§6.3 设计含义的分量会变。影响：设计结论的力度而非方向。把握：高。
3. 样本语境错位（§4.4）：论文称面向“本科水平学习情境”，但参与者是 CloudResearch 众包工人（18–73 岁，M=37.02 岁），与真实学生群体的动机结构和对 chatbot 的既有心智模型差别不小；Tutee 组“教 chatbot 很奇怪”（3/24）这类反应可能高度依赖人群。影响：向真实课堂外推的可靠性。把握：中。

#### 对我的价值
论文本身的发现（直接用于教学智能体主线）：
- 一张有实验支撑的角色—效果权衡表：Tutee 高认知投入但高压力、Peer 高吸收低压力但可能流于附和（参与者原话“感觉被奉迎”）、Challenger 在低压力下提升感知批判性思维（5.62 vs 3.74，C>B***）。设计辅导 agent 角色时，这是比单角色论文更可比的参考点。

- 附录 A 三套提示词（筛查→状态更新→生成）是可复用的工程模板，尤其是 Tutee 的知识状态 JSON 更新与 Challenger 的五类提问选择逻辑。

我的推断：
- 对 LLM Agent 通用兴趣（工具调用、多智能体协作与评测）用处有限：这是单 agent 的人机交互研究，无 agent 间协作或工具使用成分；价值在评测方法与角色设计，不在架构。
- 与翻译智能体、生物智能体两条主线基本无关；唯一沾边的可迁移点是实验范式本身——若要比较“用户向不同角色 agent 解释译文或翻译决策”的编辑质量与体验，这套四条件组间设计加过程编码可直接复用（论文本身未涉及翻译场景，此为我的推断）。

值得精读。它是教学智能体主线（learning-by-explaining、角色化辅导 agent）的直接对口实证，角色权衡表、编码方案、提示词模板拿来即用；但要记住其证据主体是单次会话的行为与主观指标，客观成绩是空结果，交互编码比较未经统计检验。

### [BioReason: Incentivizing Multimodal Biological Reasoning within a DNA-LLM Model](http://arxiv.org/abs/2505.23579v2)

`2505.23579v2` · 2025-10-24 · [PDF](https://arxiv.org/pdf/2505.23579v2)

#### 概览
论文类型：方法论文（多模态架构 + SFT/GRPO 训练配方）为主，附带一个新基准（KEGG 推理数据集）。
BioReason 把冻结的 DNA 基础模型（NT-500M 或 Evo2-1B）输出的 per-token embeddings 经一层线性投影拼入 Qwen3（1.7B/4B）的输入序列，先用 SFT 教它在 `` 标记内生成多步生物推理再给最终疾病答案，再用 GRPO 按答案正确性加奖励，用于变异致病性预测与疾病通路推理。最硬的一条证据是表 1：KEGG 任务上 Evo2+Qwen3-4B(+GRPO) 达 98.28% 准确率，超过最强单模态基线 Qwen3-4B 的 90.00%（290 个测试点，温度 0 单次解码）。我的总体判断：结果在其设置下内部自洽、代码与数据公开，但没有隔离 DNA 通路贡献的消融，也没有与该任务的领域 SOTA 对比，摘要层面的主张表述偏强。

#### 问题与思路
- 要解决的问题：DNA 基础模型（NT、Evo2、HyenaDNA 等）在剪接识别、变异效应等判别任务上表现好，但输出的是分数，无法给出机制解释；LLM 有推理能力和领域知识，却把 DNA 当普通字符串，用不上预训练序列表示。作者称这阻碍了从基因组数据到机制性洞见和可检验假设的转化（第 1 节）。变异到疾病机制的因果解释对疾病研究有直接价值，这个问题本身值得做。
- 论文对比的几类做法及不足（2.1–2.3 节）：DNA 基础模型接判别头，只有分数没有解释；纯 LLM 把 DNA 序列当文本字符串拼进 prompt（其 LLM-only 基线即如此，表 1、表 2）；ChatNT 已将 DNA 基础模型表示接入 LLM 做多任务对话，但作者称其未针对复杂生物推理训练（2.2 节）；BEND 类基准只测预测能力，不测多步推理（2.3 节）。
- 核心直觉：把 DNA encoder 的 embeddings 当作 LLM 的“感知输入”，与文本 query 同处一个注意力序列；SFT 阶段用推理轨迹示范“变异→蛋白功能→通路扰动→疾病”的因果链，GRPO 阶段用最终答案是否命中 ground truth 强化。走一遍论文自己的案例（5.5 节）：输入是 PFN1 基因的参考序列与变异序列（含一个 C>G 突变，平均约 4,000 bp）加文本 query（含通路网络"Actin(monomeric) // PFN1* // Actin(filamentous)"和基因描述）；DNA 序列被 tokenizer 切分（超 2048 DNA tokens 截断），冻结的 fDNA 编码为 per-token embeddings，经线性投影到 LLM 维度，与 `<dna_start>/<dna_end>` 及 query 的 embedding 拼接并由 RoPE 定位；Qwen3（LoRA 微调）自回归生成：先在 `` 内输出约 10 步推理（C>G 替换→profilin-1 功能障碍→actin 动力学受损→轴突运输破坏→运动神经元退行），再输出疾病名 ALS。GRPO 奖励为：答案与 ground truth 子串匹配 +2.0、答案不超过 10 词 +0.5、格式合规 +0.5，总奖励区间 [0,2.5]（A.3 节）。

#### 证据核查
所有实验为单次运行（温度 0，seed 23，5.3 节与 A.1 节），无误差条和显著性检验；评测全部为自动指标，无人工评分环节。

#### 最脆弱的一环
KEGG 任务的答案信号可能主要来自 query 文本与 LLM 预训练知识，而非 DNA 序列语义。理由：每个 query 已包含通路网络定义与基因描述（4.1.1、5.1 节），而 LLM-only 的 Qwen3-4B（DNA 以字符形式拼入 8192 长度文本）已达 90.00 accuracy（表 1），说明文本加知识通路就能解出大部分样本；BioReason 相对它的 5.17 个百分点 SFT 增益（90.00→95.17，换算）只能证明“encoder embeddings 优于字符拼接”，不能证明模型在“推理基因组信息”。一旦这个捷径假设成立，摘要里的“multimodal biological understanding”和“深度机制洞见”就降级为“多输入拼接的分类器加风格化解释”，GRPO 的提升也可由答案匹配奖励单独驱动。检验它的最小做法：保持 query 不变，把测试集 DNA 序列的核苷酸顺序随机打乱后重测；再补一个去掉通路/基因描述的 query 消融。若打乱序列后准确率降幅很小，机制主张即不成立。

**我的质疑**：
