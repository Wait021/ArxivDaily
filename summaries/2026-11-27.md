### [Crucible: Evaluating LLM Agents in Executable Chemistry Research Environments](http://arxiv.org/abs/2611.34254v1)

`2611.34254v1` · 2026-11-25 · [PDF](https://arxiv.org/pdf/2611.34254v1)

#### 概览
论文类型：基准/评测系统论文，附大规模实证评测。论文构建 Crucible Bench：1,078 个取自 18 个已发表数据集的任务、12 个任务族，覆盖设计–制造–测试–分析（DMTA）四阶段；智能体经 MCP 调用 75 个化学工具，在沙箱内由确定性验证器对提交的 artifact 判分。最过硬的证据是全部 14 个模型在同一任务集上开/关工具的对照（Table 4：关工具后总分跌至 0.129–0.242）。我判断它作为评测基础设施基本可信（采样可复现、验证器经参考解自检、报告三次运行方差、诚实披露负结果），但摘要里“合成规划与闭环优化最难”“总分不预测优化表现”两条结论的证据链偏薄。

#### 问题与思路
- 要解决的问题：化学 QA 基准（ChemBench 等）只测知识问答，测不出“配置专业软件、解读输出、得到化学有效结果”的能力；已有执行式基准没有覆盖化学研发全流程的。对造化学/药物智能体的人这是真实痛点：论文反复论证“工具跑通、输出格式正确”与“结果化学正确”是两回事，且工具型智能体可能钻评分规则空子。
- 之前的做法差在哪（论文对比的三类，Table 1）：① QA 类（ChemBench、ScholarChemQA、GPQA）不涉及工具与执行；② 通用科学智能体基准（ScienceAgentBench、DiscoveryBench、LAB-Bench、SciAgentGym、FrontierChallenge）化学域覆盖极少，最多的也只占 6 域中 2 个；③ 化学专用可执行基准各测一个点：MDArena/MDGym 只测分子动力学，SMDD-Bench/MolDesignBench 只测分子设计，ChemCost 只测采购成本，Guo et al. 只测催化机器人流程。另外 ChemCrow、Coscientist 等智能体的工具绑死在各自框架里，无法跨系统复用比较（§2.2）。
- 核心直觉：化学研发各阶段都产出可检验的 artifact（一条路线、一个能量、一份协议、一个结构），已发表数据集自带参考答案、化学上有公认数值容差，所以能用任务特定的确定性规则判分，绕开 LLM 裁判的偏差。走一个例子（Figure 6，SIM-1）：输入两个互变异构体的坐标、600 s 计算预算、目标“dE，对标 CCSD(T)/CBS 精度，容差 1.0 kcal/mol”；GLM-5.3 先跑 4 次 MP2 小基组（得 −5.39/−5.43 kcal/mol），单发一次 CCSD(T)/def2-SVP 计时 58.08 s 判断可负担，再补 5 个单点，手工做 focal-point 组合得 −4.86，提交 −4.8；验证器对照参考 −5.44，误差 0.64，满分。反例（Figure 4b）：DeepSeek-V4-Pro 的 8 个计划计算有 4 个被预算拒绝，它按比例缩放另一构象的修正补缺，提交 4.50（参考 2.25），0 分。两次的工具都“成功运行”，得分只取决于数值的化学正确性。

#### 最脆弱的一环
SYN 两族共 300 个任务（占总分 27.8%，换算）的判分标准是“与专利参考一致”：SYN-1 要求 10 条候选路线中出现与专利路线树编辑距离为 0 的一条，SYN-2 要求试剂、溶剂、温度与专利记录逐角色匹配。一旦把“化学有效但不同于参考”改计为正确，“合成规划是最难领域”这一摘要级结论和由 SYN 权重主导的总分排名都要重算——论文自己的错误分析（§5.1）报告两个 DeepSeek 模型在 SYN 的失分更多来自“与专利参考不一致”而非不可用路线，说明这部分低分测的是复现特定参考的能力。最小检验：对已提交的 SYN-1/SYN-2 artifact 用纯有效性验证器（每步反应合法、叶子全部在可购库存内）重判一遍，重算域分与模型排名。

#### 边界
**作者承认的局限**
- 最强模型总分 0.545，“可靠使用化学软件仍是挑战”（§6）。
- SYN-3 上最优模型只追平常数预测器：最佳常数答案（83%）得 0.26，最佳模型 0.260（附录 B、Table 3），该族当前无判别力。
- 智能体固定为单 ReAct 循环，无规划器、无多智能体、无自反思模块（§4.1），所有"agents"结论限于这一脚手架。
- 湿实验用 Opentrons/PyLabRobot 模拟器与已发表测量值，没有真实实验（§3.2）。
- SIM-4 仅 33/50 个 MDArena 任务提供可满分参考解，另有 154 个任务因参考解在环境内不可复现被删（§3.1、附录 B），基准偏向工具链能复现的任务。
- 领先模型总分接近（§4.2），作者未强行分出高下。

**我的质疑**
1. 训练污染未分析（§3.2 只防运行时检索）。影响：ANA-1（结构鉴定答案唯一且公开）、SYN-1、OPT-1 的分数解释无法排除记忆成分。把握：缺失本身确定；影响幅度不确定。
2. 分族方差与显著性未报告，仅有总分跨三次运行的 std ≤0.015。影响：OPT-1 领先差 0.023、总分冠亚差 0.005 都与 std 同量级，分域“第一名”类结论（Ling 领先 OPT-1、Gemma-4-31B 领先 SIM-1）可能不稳。把握：较高。
3. 9,587 条失败答案的错误归类流程未报告（§5.1、附录 D）。影响：78%、90/98 这类错误结构数字的可信度。把握：中高。
4. 模型池不含闭源旗舰（Table 3 名单以开放权重系与 GPT-oss 为主），“最佳 0.545”的天花板只在池内成立；文中也未见基准与工具的发布链接或许可信息，第三方复用不确定（就所提供文本）。把握：高（就所列名单而言）。

#### 对我的价值
论文本身的发现（与方向②直接相关）：
- DES-1 含 SMDD-Bench 先导优化任务（Boltz-2 结合概率 >0.7、相互作用指纹相似度 >0.75、Tanimoto ≥0.7 等硬约束，Table 6）；OPT-1 是预算内闭环条件优化。药物发现智能体的“分子设计”与“实验优化”两个环节都有了可执行评测件，且最强模型在 OPT-1 也只到 0.464，留出的正是研究空间。
- 头部模型在 Suzuki 优化中固着 XPhos/SPhos 先验、少测实际更优的三苯基膦，OPT 得分因此低于其余模型（§4.2）：做实验规划智能体可直接引用的“先验压过证据”实例。
- token 成本与总分错位：DeepSeek-V4-Pro 以约少 30% 的 token 略胜 MiMo-V2.6-Flash（§4.2）；固定推理预算下选型应看成本–分数联合口径。

我的推断：
- 若为生物医药智能体做评测，OPT-1 的模式——已发表高通量数据 + 查询预算 + 以同预算随机搜索为基线的归一化确定性评分——可脱离化学套用到生物测定数据上做闭环实验评测；“发布前参考解须在本环境得满分”的自检与按标识符哈希定序采样，是防验证器误伤、保可复现的工程手段，值得照抄。
- 7 个分域隔离的 MCP 服务器 + 每任务限定工具子集 + 10–100 次调用预算 + 开/关工具对照 + token/步数成本报告，是一套可整体照抄的工具调用评测环境架构。
- 方向①：论文弃 LLM 裁判、改用确定性 artifact 验证的论证（§3.3，引裁判偏差文献）可迁移到富结构文档翻译评测——XML 标签闭合、幻灯片版式不变量这类结构约束可机器判分，作为文档级译文质量的确定性检查层。方向③：无直接相关。

#### 结论
值得精读：与方向②（药物发现与自动实验智能体）及通用智能体工具调用评测两条线正面重合，其验证器构建与负结果报告在基准论文中属少见的严谨；若你只做①③，读 §3.3 的判分设计即可。

### [LectūraAgents: A Multi-Agent Framework for Adaptive Personalized AI-Assisted Learning and Embodied Teaching](http://arxiv.org/abs/2606.16428v3)

`2606.16428v3` · 2026-07-04 · [PDF](https://arxiv.org/pdf/2606.16428v3)

#### 概览
论文类型：系统/框架论文（主），附带专家 rubric 评测与一次小规模用户研究（次）。论文用一个分层多智能体流水线（ProfessorAgent 统筹研究、规划、生成、评审到“具身”授课）解决个性化学习系统大多只决定推荐什么内容、很少决定内容如何交付的问题。最过硬的一条证据是 280 个生成讲次、5 位专家按加权 rubric 的评分（表 4：7 个模型 AAR 64.1%–80.4%），以及与三个已有系统/框架的对比（表 5：Overall 71.6% vs 52.2%–60.5%）。我判断可靠程度中等偏低：消融、显著性、评分者一致性均未报告，对比实验的公平性条件缺失，结论多处超出实验实际覆盖。

#### 问题与思路
- 要解决的问题：现有教育智能体要么做虚拟课堂模拟（SimClass、EducationQ、MathVC），要么做文本课程内容生成（Instructional Agents、EduPlanner、FACET、GenMentor）；作者引手势与板书有助注意引导、降低认知负荷的教育心理学证据（[5–7]），主张应把“按学习者画像生成内容”与“边讲边写、画的具身授课”接成端到端流程。
- 之前做法差在哪（论文自己对比的几类）：模拟类困在虚拟环境；单智能体/提示工程类辅导（如 SocraticLM）无评审回路、不建模交付方式；内容自动化类纯文本交付；讲义视频自动化（AutoLectures、PASS）有动作线索但无个性化、无端到端。
- 核心直觉：把教授—下属的科层关系搬进多智能体系统：教授（Rank 1）定标准并验收，规划者（Rank 2）做验证，执行者（Rank 3）分工产出幻灯片、讲稿、语音、动作序列；授课时教授按词级时间戳在幻灯片上同步执行注记动作。
- 具体例子（论文附录 B.1.1 的示例命令）：输入 = 讲题 "Intro to Data Structures and Algorithms"、画像 "Taylor，高中生，喜欢篮球，偏好深入技术细节"、24 张幻灯片、模型 gpt-5.2、Google 检索。流程：① ProfessorAgent 开 Swarm-of-Ranks 群聊（9 种消息类型，表 2），LecturePlanner 初步研究后写讲次计划，教授审改直至批准；② SlideAgent 用结构块（定义/例题/公式/问题等）生成 HTML 幻灯片，图片按篮球主题生成或检索；③ ScriptAgent 按画像写每页讲稿；④ SpeechAgent 用 Kokoro TTS 合成语音，Whisper 提取词级时间戳；⑤ TasaAgent 把幻灯片区域与讲稿语义分段打标签（Pedagogical/Personalized/Salient/Adaptive/Assessment），为每段分配 Rough Notation（高亮/下划线/圈注）或 Handwriting 动作并给出理由；⑥ 各级评审与 agent 自反思通过后进入授课，ProfessorAgent 以 3D 持笔手在对应区域执行注记并与语音同步。输出 = 完整讲次包（计划、研究报告、幻灯片、讲稿、语音、动作序列、笔记、学习指南、测验）。

### [PPTArena: A Benchmark for PowerPoint Editing](http://arxiv.org/abs/2512.03042v3)

`2512.03042v3` · 2026-07-02 · [PDF](https://arxiv.org/pdf/2512.03042v3)

#### 概览

论文类型：基准论文（主）＋配套智能体方法（次）。PPTArena 用 100 个 deck、2,125 页、1,340 条编辑任务（每条配人工 ground-truth deck 与逐样本 style-target 评分细则）评测“按自然语言指令就地编辑 PPT”，由两个 VLM 判官分别从结构化 diff 打指令遵循分（IF）、从渲染截图打视觉质量分（VQ）；配套的 PPTPilot 智能体在 python-pptx 代码生成与直接 OOXML 补丁两条路径间路由，加最多三轮渲染校验反思。最过硬的证据是 Table 7 消融（强制 XML 单路径时 IF 从 2.36 跌到 0.95）与换 Gemini 3.1 Pro 判官后排名不变（Table A：PPTPilot 2.45/2.74 仍居首）。总体判断：“任务很难、现有系统都差”的结论可信，基准可作评测基建；但摘要“超 10 个百分点”的优势主张在文中找不到对应切片表格，在其自选难例子集上换算后不足 4 个百分点，引用具体数字前需自核。

#### 问题与思路

- 要解决的问题：智能体能否可靠地编辑“已有的” PPT——定位正确元素、改对、不伤及别处。作者的理由：真实 deck 主要靠反复修订而非从零生成；把幻灯片当位图或做文本→幻灯片生成都丢掉了编辑所需的形状树、母版布局、主题色槽、z-order。执行端另有现实约束：OOXML 对格式错误零容忍，VLM 幻觉输出会直接产生坏文件。
- 论文自己对比的旧做法及短板：① 图像/PDF 光栅化基准丢对象与样式结构（引言）；② 文生幻灯片管线（AutoPresent、PPTAgent 一类）面向生成，不满足就地编辑约束；③ PPTC/PPTC-R 在合成模板 deck 上做 API 级 diff 评测，作者按其管道测得 GPT-5 成功率 92%、Gemini 3.1 Pro 88%（附录 C.1），已近饱和；④ T2US 的 379 条 prompt 由 56 个底层任务改写而来、每例编辑很少超过 4 步（附录 Table C）；⑤ 并发且同名的另一篇 PPTArena（[13]）走 GUI 路线、仅 12 个源文件——两篇同名，检索引用时务必区分。
- 核心直觉：把编辑当“对 deck 语义的结构化程序”来做和来评。执行端承认没有单一万能接口：批量、内容为主的操作（翻译、全局替换）用代码生成可靠；细粒度结构改动（母版、主题、单形状几何）用直接 XML 补丁精确；由轻量路由器选择，渲染后校验反思。评测端把“做没做对”（IF，看结构 diff，能查出“把对的文字贴到错的页”这类 API diff 查不出的错误）与“做得如何”（VQ，看截图）拆给两个判官，逐样本 rubric 消歧。
- 具体例子（Fig B 的 22 页阿语 deck，指令“翻译并改为左到右排版”）：输入是原始 .pptx 加指令。第一步，路由器（GPT-5 nano 或 Gemini 3.0 flash）读指令与 deck 的 JSON 摘要，判定为跨 22 页批量文本操作，送程序化路径；第二步，一次 LLM 调用产出内容改写计划，再以 JSON 摘要加相关截图为上下文生成 python-pptx 代码并执行；第三步，校验器确认产物是合法 PPTX 并渲染检查，失败则反馈重试，最多三轮。输出是编辑后的 deck，由 IF 判官（GPT-5.2，温度 0.2）按预测与 GT 的 JSON/XML diff 加 style target 打 0-5 分，VQ 判官按两侧截图（SSIM 筛页、每 5 页一批）另打 0-5 分。

#### 问题与思路

- 要解决的问题：DocMT 需要处理词汇一致性、共指消解等长距离话语现象；整篇一次翻译有漏句、上下文稀释与解码成本随长度二次增长的问题（论文引 Wang et al., 2025）。
- 论文对比的两类旧做法的缺陷：检索式方法按语义相似度取历史句，把上下文当无结构集合，可能打断线性叙事；已有图方法（GRAFT、TransGraph）靠 LLM 做成对边分类建图、成本高，且只取一阶邻居，拿不到多跳话语路径。
- 核心直觉：话语相关性可用三个便宜信号近似——embedding 余弦相似度（主题）、邻接（局部连贯）、TF-IDF 关键词重叠（术语）；在图上从目标句回溯随机游走并偏向“能延伸更长链”的节点，就能既贴住邻接句又沿语义边跳到远处，而建图不花 LLM 调用。
- 用论文自己的例子（Table 6，SAP）走一遍：输入是 ERP 文档第 i 句 "If jobs have been scheduled for posting periods…"，"posting" 在此域应译“过账”，定义在 10 段之前。① 每句为节点，对每对 (i,j)（j<i）计算 w_ij=α·S_sem+β·S_seq+γ·S_key（α=0.2、β=0.3、γ=0.5，S_sem 经 τ_sem=0.6 截断）；② 动态规划算各节点深度启发 φ；③ 从 x_i 按 P(v_next|v)∝w·(φ(v_next)+1)^λ（λ=2.0）回溯采样，取至多 L=4 个先前节点、距离超过 100 停止；④ 路径按文档顺序反转，连同各句已有译文和 x_i 拼成 prompt，LLM 输出 y_i。10 段前含 "elimination posting" 等关键词的句子经 S_key 边被选中，模型译出“过账”；Window 基线取不到，译成“发布”。注意两个基准里“段落=单句”，节点实际是句子。

4. 两个基准的节点都是单句（3.1 明说），"paragraph"级方法在真正多句段落上未验证，更不涉及 PPT/XML 类富结构文档。影响：方法外推到我的场景属于未测试区域。把握：高（事实性）。
5. 超参在未说明的"validation set"上选定，存在向测试集调参的余地；Table 3 的 backbone 未注明。影响：可复现性与部分证据的可信度。把握：中。

#### 对我的价值

与方向②（生物智能体）、③（教学智能体）基本无关；唯一可泛化的机制是“多候选 + 嵌入聚类取质心”这种无监督 self-consistency，与领域无关。

与方向①直接相关的论文本身发现：在 SAP（IT 域）上，关键词重叠边消融损失最大（-0.5），且 Window 常胜过纯语义检索——技术文档翻译中局部连贯与术语一致优先于全局主题相关（该设置下显示，不当作普适规律）。用 embedding + TF-IDF 建图替代 LLM 建图，在不增加 LLM 调用数的前提下拿到小幅增益，是翻译智能体流水线降本的一条可行路线。其评测做法（主指标只有 d-BLEU，话语指标仅单一设置、无人工评测）是我自己做文档级评测时应避免的样板。

### [Warning About AI Fallibility Increases Help-Seeking in an Intelligent Tutoring System](http://arxiv.org/abs/2606.03822v1)

`2606.03822v1` · 2026-06-02 · [PDF](https://arxiv.org/pdf/2606.03822v1)

#### 概览
论文类型：实证研究（教室随机对照实验，AI 教育方向短文）。论文在 252 名日本七年级学生中使用两个只有弹窗文案不同的数学智能辅导系统（ITS）版本——一个警告"代理 Maddox 可能犯错"，一个只说"请仔细阅读"——检验轻量透明提示对解题行为的影响；最硬的证据是随机分配下 Mistake 条件每步提示请求数为 1.09（SD 1.26）、NoMistake 条件为 0.75（SD 0.88），β=−0.33，t(235)=−2.33，p=.02。我判断：设计干净（两版本系统行为完全相同、对照也有弹窗），但统计细节多处未报告、无学习结果测量，结论应视为该设置下的初步证据。

#### 问题与思路
- 要解决的问题：LLM 进入教学系统带来幻觉风险，实践中的常见应对是加一句"AI 可能犯错"的警告；但这类轻量透明提示在真实教室中是否改变学习者行为，此前缺乏实证（引言，作者称 "prior work has not provided empirical evidence"）。
- 之前的做法差在哪：论文只对比了两类相关工作。其一，错误参与研究：erroneous worked examples（引 Booth 等）和 LLM 幻觉反馈研究（引 Steinbach 等 2025）显示错误本身未必损害学习，关键在于学习者如何参与错误；其二，HCI 的"AI 安慰剂效应"研究（引 Kosch 等 2023）：用户会因感知的 AI 能力改变行为，即使底层性能不变。本文把"只改披露、不改系统"的这套范式搬进教室。
- 核心直觉：把系统输出从权威答案重新定价为需要核验的信息，学生在不确定时会更愿意请求提示。具体走一遍：学生在线性方程组 ITS 里做题（先拖拽选步骤，后自由输入），每种解法引入时弹窗一次、共三次；Mistake 条件看到 "Maddox can make mistakes, so be careful to read his messages thoughtfully and think critically about the guidance you receive!"，NoMistake 条件看到 "Please read Maddox's messages carefully!"。提示与反馈全部规则式硬编码，无 LLM、无植入错误（第 2.2 节）。输出：日志显示 Mistake 组每步请求提示 1.09 次、NoMistake 组 0.75 次（绝对差 0.34 次/步，约 45% 相对提升，换算），错误率与每步用时无组间差异。

#### 对我的价值
- 教学智能体主线（③）直接命中。论文层面的发现：一句披露 AI 可错性的文案把每步提示请求从 0.75 抬到 1.09（约 45% 相对提升，换算），错误率与用时不动，系统行为两版相同。对 LLM 导师系统的含义：警告文案是行为级杠杆，会推高求助量，而求助是适应性行为还是刷提示需另行度量。
